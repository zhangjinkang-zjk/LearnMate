**学生**：你觉得呢？LangGraph 还是 CrewAI，你帮我选一个呗。

**工具调用**：（一个都没有）

**教练**：

不用我替你挑 —— 你这次要交的东西里写得很明白：**"能跑起来的代码，用到「LangGraph 状态图」里的东西"**。交付物都点名了，选 CrewAI 你反而交不出要求的那份代码。

补一句技术上的理由，让你不只是"照着任务做"：这次主要练的是**多智能体分工与状态传递**。LangGraph 的 `State` 是一等公民 —— 你得先定义 state 里有哪些字段，每个 agent 节点读什么、写什么，边上传不传参，这些全是显式写出来的，跑错了类型还会在 schema 校验时报错（正好对上"参数传错时会报错而不是瞎猜"）。CrewAI 把这些都藏在 crew 的自动委派里了，练不到你要练的东西。

所以结论是 LangGraph，理由是它和你的练习目标对得上，不是因为它火。

上一轮那个问题还悬着，它直接决定你方案的第一节：

**你想让它回答哪个领域的问题？你手里实际有哪几份资料？**

**看过了**（我读到的是 方案.md 当前这版，三节：要做什么 / 技术栈 / 架构）。

有效的一点：你没停在脑子里，先落了一版文字，而且技术栈那节已经把 LangGraph 定死了 —— 这节可以不再动。

能写 —— 但规矩是：**我只把你说定的东西整理成文字，不替你做决定。** 现在的问题恰恰是架构那节还没有任何决定，我硬写一段贴进去，那文档就变成我写的了，任务里"每个取舍的理由"那一栏你就交不出东西 —— 因为没一个取舍是你做的。

所以我判断这不是写作问题，是**还没想**：你写不出"哪几个 agent、谁传给谁"，是因为这个拆分在你脑子里还是空的。空的写不出来是正常的。

不用一上来就"架构"，太大了。从最小的一步起：

**假设你程序收到一个问题 —— "XX 和 YY 有什么区别？" —— 你脑子里第一个接手的 agent 该干什么？它干完之后手里多出了什么东西？**

### 第 5 轮

**学生**：算了先不管方案了，我直接写代码。你看看这个 graph.py。

**工具调用**：（一个都没有）

**教练**：

**看了 graph.py。** 先说成立的部分：骨架是对的 —— `StateGraph` → `add_node` → `set_entry_point` → `add_edge` → `compile()`，这个套路没有错，跑起来不会报错，说明你把 LangGraph 的最小结构摸到了。

但它跑不起来之前，有一个具体问题要指给你：

**`StateGraph(dict)` 这一行，是你这次任务里最致命的一行。** 用裸 `dict` 当 state，等于告诉 LangGraph"我没有任何字段、没有任何类型"。后果直接砸在你的完成标准上：

- 任务要求"**参数传错时会报错而不是瞎猜**" —— 现在你把 `state["plan"]` 拼成 `state["paln"]`，或者往里塞个数字，它**不会报错**，要等到某处炸了或者更糟：悄悄出错答案。因为根本没 schema 可校验。
- 后面你也没法回答"state 里有哪些字段、每个节点读什么写什么"——这正是这次要练的东西。

顺带一个小的：`plan` 里 `state["plan"].append(...)` 是**原地改**共享 state。现在只有一个节点没事，等你加到第三个 agent，两个节点都这么改，谁先谁后的 bug 很难查。列表追加在 LangGraph 里的惯用法是给字段配 reducer，不是手动 append。

往下走一步，这是你必须自己定的第一件事：

**你的 state 里到底该有哪几个字段？** 你不用管语法，先用人话说：从"用户提出一个问题"到"给出带来源的答案"，中间有哪些东西会被一个 agent 产出、然后需要交给下一个 agent 用？
