## 一、诊断问答

### 第 1 问（难度 easy）

**导师问**：工具调用这个词你熟吗？用你自己的话说说它在问答流程里起什么作用，比如什么情况下该用它、什么情况下不该。

**假学生答**：我理解的工具调用，就是模型在回答前先判断"这个问题我自己答不了，得调个函数"，比如用户问天气，模型就去调一个查天气的 API，拿到结果再组织语言。像常识问题这种直接能答的，就不该用，否则反而绕远了。我看过 OpenAI 和 LangChain 的文档，知道要先定义函数的 schema 再写处理逻辑，但还没亲手写过一个能跑起来的例子。

**判分**：答对（100.0）

**给学生的反馈**：你讲清了该用不该用的典型场景，调用链路也大致对，但对参数填充的边界和结果可靠性还不够敏感，下一步可以补上。

### 第 2 问（难度 medium）

**导师问**：假设你那个问答应用里配了查天气和算汇率两个工具，用户突然问"我该带伞吗"，从拿到这句话到给出回复，你会怎么走一遍流程？

**假学生答**：我觉得模型拿到"我该带伞吗"应该先判断出这问题背后其实是要查天气，而不是直接去调算汇率那个工具，它得推断出地点、可能还要确认时间，然后发起查天气的工具调用；拿到"明天中雨"这类结果后再把结论翻译成"建议带伞"这种话回复用户。另外我猜对话里要是之前提过所在城市，就直接用，没提的话可能还得反问一句。这套判断逻辑我在 LangChain 的 ReAct 文档里看过大概流程，但具体工具返回的字段怎么接、模型判断要不要调工具这一步实际长什么样，我还没真写代码验证过。

**判分**：答对（100.0）

**给学生的反馈**：流程链路和参数追问都讲清了，也说明了结论翻译这步不必再调工具，只是工具失败时该怎么兜底还缺一步。

### 第 3 问（难度 medium）

**导师问**：你真跑起来后，用户问天气它却没调工具、直接编了个答案，你会从哪一环开始排查、怎么定位问题？

**假学生答**：我还没真跑起来过（这个 bug 我没亲身踩过），但按我看 OpenAI function calling 文档时的印象，我会先打出发给模型的原始请求，看 `tools` 到底传没传进去、schema 对不对——最常见的就是我漏了把工具挂到那次调用上，或者字段写错没被识别。确认传进去了再看返回的日志，模型是压根没生成 `tool_calls`、还是生成了但我在代码里没接住没把结果回传，这两段打出来基本就能定位；再往后才怀疑是不是工具描述写得太含糊，让模型觉得不调也能答。这些是文档里看过的排查思路，具体哪一步我真卡过，得等我自己写出来才知道。

**判分**：答对（100.0）

**给学生的反馈**：你能把工具没挂上、模型没发起调用、代码没接住结果这几段分开打日志核对，还把工具描述含糊列为靠后的怀疑点，排查路径和依据都对得上。
