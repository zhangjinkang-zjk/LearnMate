## 一、诊断问答

### 第 1 问（难度 easy）

**导师问**：用你自己的话讲讲，智能体里的“工具调用”到底是在做什么？比如从模型决定调用到拿到结果返回，中间发生了什么。

**假学生答**：简单说就是：模型自己不直接干活，而是输出一段结构化的内容说“我想调这个工具、参数是这些”，然后我们代码去真正执行这个调用，把结果再塞回对话里让模型继续生成。我看过 LangChain 文档里那套流程——模型返回的是 tool_calls 而不是最终答案，得我们自己把工具的执行结果包成一条 tool message 发回去。但具体怎么解析那个结构、参数不对时怎么处理，我没亲手写过，只在教程视频里看过大概。

**判分**：答对（100.0）

**给学生的反馈**：你把模型只出意图、外部代码执行再回传的分工和流程讲清楚了，还提到 tool message 这个细节，欠缺的是对参数异常这类边界的处理经验。

### 第 2 问（难度 medium）

**导师问**：假设你的问答应用里，模型要调一个查天气的工具，结果参数里少了城市名，这一步你会怎么处理？比如代码上会加什么判断？

**假学生答**：我可能会在拿到 tool_calls 之后先自己检查一下参数，比如看 city 字段是不是空的，缺了就不执行调用，直接把“缺少城市名”这条信息作为 tool message 发回去，让模型自己去追问用户要哪个城市。看过文档里说 schema 校验这层一般是交给模型用结构化输出自己保证的，代码里更多是防御性检查，但参数校验在真实调用里实际怎么卡住、报错长什么样，我没写过，只是教程里提到过要处理这种情况。

**判分**：答对（100.0）

**给学生的反馈**：你先在执行前检查参数是否齐全、缺了就不调用而是回传信息让模型补问，这个防御思路和对话影响都说清楚了，只是对几种兜底处理方式的取舍还没展开。

### 第 3 问（难度 hard）

**导师问**：你跑通了一遍流程，但发现模型在同一个工具上反复打转、答案越来越偏，你会从哪几处下手排查？比如日志里你会重点看什么？

**假学生答**：我会先去看工具执行返回的结果是不是有问题——比如是不是每次都返回同一条重复内容，或者结果太长没截断把上下文冲掉了，这样模型拿到的东西本身就不对，自然会一直重试。另一个地方是看对话历史里 tool message 的格式对不对，教程视频里提过如果 tool_call_id 没对上、或者消息顺序乱了，模型会"看不懂"自己上一轮干了什么，就容易原地打转。不过说实话，我真没在日志里排查过这种死循环，具体日志里长什么样、用什么关键字去搜，我只在文档里看过，还没上手写过。

**判分**：答错（0.0）

**给学生的反馈**：你识别了工具返回和消息格式这两处故障层，但还没说清怎么用日志定位跑偏的起点，也没给出限制调用轮数之类的止血手段。
