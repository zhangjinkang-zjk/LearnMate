# LearnMate 学习进阶设计草案

更新时间：2026-09-04

## 一、模块定位

进阶学习不是更难的一轮基础讲解，而是把已经学过的方法迁移到用户的真实目标中。

```text
基础讲解：理解概念、方法与典型例子
进阶学习：面对约束做判断、完成交付、用证据验证结果
学习工作区：承载进阶任务所需的材料、笔记、操作与提交
```

进阶模块需要读取四类已有信息：

- 学习方向：用户要学的领域
- 学习目标：就业、完成项目、系统学习、转行或自定义目标
- 能力诊断：薄弱知识点、最近成绩、建议难度
- 学习路径：当前节点、已完成内容、可用资料和下一步动作

## 二、目标驱动的任务类型

同一学习方向不能给所有用户相同的进阶任务。系统根据学习目标选择任务模板：

| 学习目标 | 进阶任务 | 主要交付物 | 验收方式 |
| --- | --- | --- | --- |
| 准备就业 | 岗位情境任务、故障排查、方案答辩 | 处理方案、技术说明、答辩记录 | 岗位能力项与解释质量 |
| 完成项目 | 项目里程碑、方案设计、实现验证 | 项目方案、运行结果、测试证据 | 需求覆盖、结果可复现、指标达标 |
| 转入新方向 | 能力迁移任务、差距补齐挑战 | 能力映射、补齐任务、作品证明 | 是否能把旧经验迁移到新领域 |
| 建立系统基础 | 综合知识任务、跨知识点案例 | 知识结构、分析过程、综合结论 | 概念连接、方法选择、迁移能力 |
| 自定义目标 | 从目标中提取任务、约束和成果 | 与目标匹配的可验证成果 | 由目标反推的验收标准 |

## 三、学习闭环

每个进阶任务遵循同一条闭环，不把路径、案例和工作区割裂成互不相关的页面。

```text
系统生成目标任务
  -> 用户阅读背景与验收标准
  -> 在工作区查看文档、日志、数据或案例
  -> 用户作出判断并提交阶段成果
  -> 系统依据量规评价并指出证据缺口
  -> 不合格时生成针对性补强任务
  -> 合格后沉淀作品/记录并解锁下一阶段
```

## 四、页面布局

进阶学习首页只展示一个当前任务，避免把大量内容塞进右侧、左侧却只有少量状态。

```text
┌────────────────────────────────────────────────────────────┐
│ 进阶学习                                                   │
│ 当前方向 / 目标类型 / 当前阶段 / 总进度                    │
├────────────────────────────────────────────────────────────┤
│ 任务背景与目标（主区域 60%）       │ 验收标准与能力缺口 40% │
│ - 要解决的问题                    │ - 本次重点能力          │
│ - 已知条件与限制                  │ - 必须提交的成果        │
│ - 当前阶段任务                    │ - 通过标准              │
│ [进入任务工作区]                  │ - 系统为何推荐该任务    │
├────────────────────────────────────────────────────────────┤
│ 阶段进度：理解情境 -> 制定方案 -> 验证结果 -> 复盘答辩      │
└────────────────────────────────────────────────────────────┘
```

“系统推荐”不再是一句泛泛建议，而是明确说明：

```text
推荐原因 = 用户目标 + 当前薄弱点 + 已完成基础内容 + 本次成果
```

例如：

> 你准备相关岗位就业，已经完成检索基础，但“效果评估”诊断正确率为 40%。本次先完成一次召回结果对比，并提交指标解释；通过后再进入完整知识库案例。

## 五、现有后端复用

优先复用现有能力，不另造重复服务：

- `GET /learning_path/current`：读取当前路径、节点、薄弱点、成绩与下一动作
- `GET /path/{path_id}/node/{node_id}`：读取当前节点、资源和进度
- `POST /path/{path_id}/node/{node_id}/generate-resources`：生成文档、案例、阅读材料等资源
- `POST /path/{path_id}/node/{node_id}/classroom`：生成互动课堂和情境内容
- `POST /path/classroom/chat`：在案例过程中追问、澄清和答辩
- `POST /path/{path_id}/node/{node_id}/generate-quiz`：生成阶段检查
- `POST /path/{path_id}/node/{node_id}/submit-quiz`：判分、更新掌握度并解锁后续节点
- `ExamRecord`、`KnowledgeMastery`、画像 `traits.onboarding`：提供诊断和个性化依据

## 六、需要补齐的后端能力

现有路径和课堂能够承载学习过程，但还缺一个明确的“进阶任务”聚合协议。建议新增薄层接口，而不是再造资源和测验系统：

```text
GET  /advanced/current
POST /advanced/start
POST /advanced/{task_id}/submit
GET  /advanced/{task_id}/result
```

接口主要负责：

- 根据用户目标选择任务模板
- 聚合学习路径、诊断结果和可用资源
- 定义任务交付物与验收量规
- 保存用户提交和评价结果
- 决定补强、重试或解锁下一阶段

底层资源生成、课堂交互、题目判分和掌握度更新继续调用现有服务。

## 七、实施顺序

1. 定义进阶任务的数据协议和目标模板。
2. 后端新增聚合服务，复用路径、资源、课堂和测验能力。
3. 前端重构 `AdvancedLearningPage.vue`，先接 `GET /advanced/current`。
4. 将“进入任务工作区”连接到带任务上下文的工作区。
5. 增加提交、评价、补强和解锁闭环。
6. 用就业、项目、转行三种目标分别完成端到端验证。
