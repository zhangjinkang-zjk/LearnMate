# 自适应学习工作台界面与功能方案

## 1. 文档目的

本方案用于指导本次比赛版本的前端界面重构和前后端协作开发。

核心目标是把产品从“资源展示型学习平台”调整为“以学习任务为中心的自适应学习工作台”，围绕一个垂直领域完成：

```text
学习定向 -> 能力诊断 -> 诊断结果确认 -> 学习导航 -> 学习工作区
    -> 阶段复盘 -> 动态调整学习导航
```

## 2. 产品定位

### 2.1 推荐比赛方向

第一版暂定方向：

> 企业知识库与智能体应用开发

该方向是一条岗位能力路径，不是单一课程。路径内部包含多个能力模块：

```text
企业知识库与智能体应用开发
├── Python 与工程基础
├── 大模型与 Prompt 工程
├── RAG 与知识库构建
├── Agent 工具调用与工作流
├── 多智能体协同决策
├── 系统评测与部署
└── 综合项目实训
```

### 2.2 核心用户价值

用户进入系统后始终能够回答：

1. 我当前的学习目标是什么？
2. 我现在掌握了什么、薄弱点是什么？
3. 系统为什么推荐当前内容？
4. 完成当前任务后，我下一步应该做什么？

## 3. 用户主流程

```text
新用户
  |
  v
学习定向
  | 选择领域、目标角色、目标项目、可用时间
  v
能力诊断
  | 结构化问答、场景判断、基础任务
  v
诊断结果确认
  | 查看画像、薄弱点和系统判断，可返回修改
  v
学习导航
  | 生成一条主路径，包含多个能力模块
  v
学习工作区
  | 内容学习、提问、练习、查看来源、AI 决策
  v
阶段复盘
  | 根据答题和交互结果更新掌握度
  v
动态调整
  | 补基础、继续练习或进入进阶挑战
```

## 4. 命名约定

| 环节 | 界面名称 | 说明 |
|---|---|---|
| 方向和目标设置 | 学习定向 | 确定用户想学什么、为什么学、准备投入多少时间 |
| 第一轮测试 | 能力诊断 | 通过问答建立初始能力画像 |
| 诊断结果 | 诊断结果 | 展示系统判断，并允许用户确认或修改 |
| 生成的路径 | 学习导航 | 根据画像生成动态学习路线，不是固定课程目录 |
| 当前学习页面 | 学习工作区 | 统一承载内容、练习、问答和 AI 反馈 |
| 阶段结果 | 阶段复盘 | 根据真实学习表现重新校准能力 |
| 总结页面 | 学习报告 | 展示能力变化、资源匹配、覆盖率和决策过程 |

## 5. 信息架构

```text
学习
├── 今日任务
├── 当前学习工作区
└── 最近学习记录

学习导航
├── 总体目标
├── 能力模块
├── 学习节点
└── 完成情况

能力诊断
├── 初始诊断
├── 当前学习画像
└── 薄弱点分析

学习报告
├── 能力变化
├── 学习记录
├── 资源匹配
└── AI 决策记录

资源库
├── 按能力模块浏览
├── 搜索
└── 收藏
```

资源库、管理后台和系统设置属于辅助功能，不应抢占学习主流程。

## 6. 全局布局

```text
┌────────────────────────────────────────────────────────────┐
│ 知班 / 智能体应用开发实训   学习  导航  诊断  报告  资源库   │
│                                                  消息  用户 │
└────────────────────────────────────────────────────────────┘
```

设计原则：

- 默认进入“学习”，而不是资源列表；
- 每个页面只保留一个主要行动；
- 页面之间共享当前领域、目标和学习会话；
- 资源、聊天、Agent 流程都服务于当前学习任务；
- 桌面端优先三栏工作区，移动端按内容、反馈、下一步顺序纵向排列；
- 避免首页堆叠大量资源卡片和无关功能入口。

### 7.5.1 学习场景编排

学习工作区不能只是“文章 + 聊天 + 题目”三栏。它应该把已有资源编排成一个围绕学习目标的可互动场景：

| 资源 | 在场景中的角色 | 主要交互 |
|---|---|---|
| 文档/阅读材料 | 主线知识内容和权威依据 | 阅读、搜索、标注、引用、让 AI 解释选中内容 |
| PPT | 可选的视觉辅助或总结材料 | 翻页、查看图示、针对页面提问；不作为唯一知识来源 |
| 思维导图 | 建立知识结构 | 展开节点、查看关联知识点、定位对应内容 |
| 案例 | 把知识放入真实场景 | 选择方案、拖拽步骤、查看后果 |
| 练习题 | 检查掌握度并产生反馈 | 答题、提交、查看错因、重新练习 |
| 视频/图片 | 展示过程、界面或实际现象 | 播放、暂停、针对时间点或区域提问 |
| AI 教练 | 串联资源并调整学习难度 | 追问、换种解释、生成例子、推荐下一步 |

文档是学习场景的知识主线，所有关键结论必须能回到已审核的文档和知识库片段。PPT 只作为视觉化辅助、课堂总结或案例演示使用；由于生成质量可能不稳定，不能把 PPT 作为唯一知识来源、唯一完成条件或唯一评测依据。生成 PPT 时仍可附带页级结构，但应标注其引用的文档段落。

### 7.5.3 工作区交互规则

1. **资源序列由系统生成**：用户看到的是有顺序的学习步骤，而不是一堆文件。典型顺序为“知识文档主线 → 思维导图梳理 → PPT 图示辅助 → 案例 → 互动练习 → 阶段复盘”。
2. **文档是主线，其他资源按需嵌入**：关键知识点必须来自文档和知识库；PPT、图片、视频和思维导图用于降低理解成本或展示过程。
3. **资源之间可以跳转**：点击文档中的知识点，可以定位到思维导图节点、PPT 图示、案例步骤和对应练习；查看 PPT 时也能回到原文段落。
4. **所有资源都有学习动作**：文档要标记重点，PPT 要完成图示问题，案例要做判断，视频要回答问题，思维导图要定位薄弱节点。
5. **AI 教练根据动作调整内容**：用户标记“不理解”时，先换用简化解释、图示或短案例；连续答对时，进入综合案例或进阶题。
6. **完成条件由任务定义**：不是打开资源就算完成，而是完成阅读、互动、练习或实训中的指定动作；单独浏览 PPT 不应算完成核心知识任务。

## 8. Agent 在界面中的呈现


点击展开后展示技术细节：

```text
学情分析：发现“语义切分”掌握度不足
知识检索：引用《RAG 实践指南》第 3.2 节
```

现有 `AgentFlowDrawer.vue` 可作为基础，但需要从“实时流程动画”升级为“可回放的决策时间线”。

## 9. 前后端配合范围

### 9.1 前端重点

- 新增学习工作区主布局；
- 重排首页、路径、诊断和资源库的优先级；
- 统一学习会话状态；
- 增加阶段复盘、下一步决策和学习报告；
- 展示 Agent 决策、知识来源和资源匹配结果；
- 以文档阅读为主线，按学习目标编排思维导图、PPT 图示、案例、练习、视频和图片；
- PPT 只作为可选辅助资源，不能替代文档、知识库来源或核心完成条件；
- 支持资源之间的关联跳转和统一完成状态；
- 保留旧资源页面，先降级为辅助入口。

### 9.2 后端重点

不需要更换 FastAPI、LangGraph、RAG 或数据库架构，重点补充学习会话和决策层：

- 新增 `LearningScene`，由后端返回有顺序的资源步骤，而不是让前端拼接多个资源接口；
- 文档作为主线资源，PPT 记录为可选 `visual_aid`，同时保存它引用的文档片段；
- 为每个资源定义用途、交互动作和完成条件；
- 对 PPT 生成结果做质量检查，质量不足时只作为附件，不进入核心学习序列；


## 10. 实施顺序

### 第一阶段：确定主流程

- 锁定垂直领域和综合项目；
- 完成学习定向、能力诊断和学习导航的页面原型；
- 准备 3 类学习者画像和一套领域知识库。

### 第二阶段：重构学习主界面

- 新增学习首页；
- 新增学习工作区；
- 将路径、内容、AI 教练和练习合并到统一学习会话；
- 保留旧页面作为兼容入口。

### 第三阶段：补动态反馈

- 增加阶段复盘页；
- 实现补基础、继续练习、进阶挑战三种决策；
- 保存 Agent 过程和决策记录。

### 第四阶段：补报告和比赛材料

- 增加学习报告和资源匹配展示；
- 增加知识来源、覆盖率和审核结果；
- 准备测试用例、部署说明和 10 分钟演示流程。

## 11. 第一版验收标准

- 新用户可以完成学习定向并开始诊断；
- 诊断结果能生成一条包含多个能力模块的主路径；
- 用户可以在同一学习工作区完成文档阅读、资源互动和练习；
- 学习工作区以审核文档为主线，并能按目标关联思维导图、案例、题目、视频、图片和可选 PPT；
- PPT 质量不足时不会阻断学习主流程，也不会替代知识库来源和核心完成条件；
- 答题结果能够触发不同的下一步学习策略；
- 页面能展示至少 3 个 Agent 的职责、过程和决策；
- 生成资源可以展示知识来源和审核结果；
- 报告页可以看到能力变化、知识覆盖和资源匹配；
- 至少准备 3 类学习者画像和 50 组左右测试用例；
- 旧资源功能仍可访问，但不再作为主入口。

## 12. 最终产品定义

> 一个面向“企业知识库与智能体应用开发”的自适应学习工作台。用户通过学习定向确定目标，通过能力诊断建立画像，系统生成包含多个能力模块的学习导航，并在学习过程中根据答题和交互反馈动态调整内容、难度和下一步任务。
