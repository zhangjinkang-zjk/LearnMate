# 外部视频接入说明（前端）

本文档说明「基础学习」页按节点拉取外部教学视频的接口、字段含义、**必须遵守的展示顺序**，以及当前已知缺陷和对应的界面处理。

后端已经做完并验证；前端需要接的部分见第 6 节。

---

## 1. 鉴权约定

和站内其它接口一致，需要登录用户的 JWT：

```http
Authorization: Bearer <access_token>
```

未登录或 token 失效返回 HTTP `401`，前端应清理本地登录态并回到登录页。不要把 token 放进 URL、日志或错误提示。

---

## 2. 接口

### `GET /path/{path_id}/node/{node_id}/external-videos`

按**指定节点**检索外部教学视频与资料。

```http
GET /path/12/node/87/external-videos?max_results=3
```

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `path_id` | path | 是 | 学习路径 ID |
| `node_id` | path | 是 | 节点 ID，**由前端传**（见 2.3） |
| `max_results` | query | 否 | 返回条数，`1~5`，默认 `3` |

统一响应包装：

```json
{ "code": 200, "msg": "success", "data": [] }
```

`data` 是一个数组，按**展示顺序**排好（见第 4 节）。

### 2.1 错误码

| HTTP | 场景 | 前端处理 |
| --- | --- | --- |
| `401` | 未登录 / token 失效 | 清理登录态，回登录页 |
| `404` | 路径无权访问，或节点不存在 | 展示"这一章的推荐视频暂时不可用"，不要暴露"无权访问" |
| `429` | 超过 `10 次/分钟/用户` | 退避重试，不要连续重发 |

> 每条路径的访问权由后端校验（创建者 / 公开路径 / 已加入）。**访问不到统一返回 404**，不区分"不存在"和"没权限"。

### 2.2 `node_id` 必须由前端传

后端**不会**自己去猜"当前节点"，这是刻意的设计，不是没做完。

服务端有一个 `current_node_id` 字段，但它取的是「**第一个** `unlocked`/`in_progress` 的节点」——用户把第 3、4、5 章都解锁后翻到第 5 章在读，它仍然返回第 3 章。后端 `advanced/service.py` 那边就是被这个坑到，才改用"最近完成的节点"当锚点。

**前端传 `FundamentalsPage.vue` 里的 `activeNode.id`**，也就是用户**正在看**的那一章。

另外：用户可能同时有好几条路径。这个接口是 `(path_id, node_id)` 二元组，**每条路径各传各的**，不要假设"全局只有一个当前节点"。

### 2.3 缓存与调用时机

- 服务端对相同节点+参数的结果**缓存 6 小时**，重复调用不再产生外部搜索开销。
- 但**第一次**调用一个节点会触发 1~3 次付费搜索。所以：
  - **切换章节时才调用**，不要每次渲染 / 每次滚动都调
  - 不要把 `max_results` 换来换去（换参数就是新的一次搜索）

## 3. 返回字段

每条结果的字段如下。**`embed_url` 是否为空，决定了渲染方式**（见第 4 节）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string | 标题 |
| `author` | string | UP 主 / 作者。**只有 B 站有**，课程平台为空串 |
| `duration` | string \| int | 原始时长，不要直接展示 |
| `duration_text` | string | **已格式化**，如 `12:34`、`3:37:17`；取不到时为空串 |
| `view_count` | int | 原始播放量，没有时为 `0` |
| `view_count_text` | string | **已格式化**，如 `5.0万次`；为 0 时是**空串**（不是 "0次"） |
| `description` | string | 简介 / 摘要，可能较长，建议截断展示 |
| `cover_url` | string | 封面图。**只有 B 站有**，课程平台为空串 |
| `page_url` | string | 原平台页面地址，用于跳转 |
| `embed_url` | string | **非空 = 可站内 iframe 播放**；空 = 只能跳转 |
| `preview_url` | string | 与 `embed_url` 同值（历史字段，兼容用） |
| `source` | string | 与 `source_label` 同值（历史字段，兼容用） |
| `source_label` | string | 来源中文名，可直接展示：`B站` / `中国大学MOOC` / `学堂在线` / `慕课网` / `掘金` / `知乎` / `GitHub` 等。**按字符串直接渲染即可，不要写死枚举** —— 白名单会调整 |

**`duration_text` 和 `view_count_text` 后端已经格式化好，前端不要再算一遍** —— 尤其 `view_count_text` 在没数据时是空串，前端若按 `"0次"` 处理会出现脏文案。字段缺失时应渲染为空，而不是 `0`。

---

## 4. 展示顺序：必须保持后端返回的顺序

**这是最重要的一条。**

后端已经按下面的优先级排好序，前端**不要自己重排**（不要按标题、按播放量、按日期重新 sort）：

1. **可站内播放的视频**（`embed_url` 非空，目前是 B 站）
2. **课程平台的视频课程**（`embed_url` 为空，点了跳转到原平台，如中国大学MOOC）
3. **图文资料**（`embed_url` 为空，兜底，只有在 1、2 凑不够条数时才会出现）

排这个顺序的原因是：**位置本身就是信息** —— 排在前面的是点开就能看的。用户对"能直接播"的期待最高，把它排在后面会让人以为都得跳出去。

### 4.1 两种渲染方式

**A. `embed_url` 非空 → 站内 iframe**

```html
<iframe
  :src="video.embed_url"
  referrerpolicy="no-referrer"
  allowfullscreen
  frameborder="0"
/>
```

> ⚠️ `referrerpolicy="no-referrer"` **必须加**，否则部分浏览器会拦截播放。

> ⚠️ **B 站外链播放器对版权受限内容会拒绝播放**（能内嵌不等于一定能播）。所以要准备兜底：iframe 加载失败 / 用户点击"在 B 站打开"时，给一个跳转 `page_url` 的出口。

**B. `embed_url` 为空 → 跳转原平台**

展示封面占位（`cover_url` 可能也是空的，要准备无封面样式）+ 标题 + `source_label`，点击打开：

```html
<a :href="video.page_url" target="_blank" rel="noreferrer">去 {{ video.source_label }} 观看</a>
```

> 现有代码里已经有对应的兜底样式（`.external-video-fallback`），可以复用。

## 5. 已知缺陷与界面应对

**这些是当前真实存在的限制，前端要按"会发生"来处理，不要按"不会发生"来写。**

### 5.1 相关性不保证 —— 5 条里可能混进 1 条不相关的

后端有一层语义相似度过滤，但它**拦不住"词撞车"**。实测：节点「大模型应用调用基础：上下文窗口与生成参数」搜出来的 5 条里，混进了一条「【计算机网络】题目讲解 **滑动窗口**协议」——因为"窗口"这个词撞车了。

**界面应对：**
- 措辞用**「相关推荐」「为你找到」**，**不要**写「精准匹配」「最适合你」
- 不要承诺条数。`max_results=3` 是上限不是保证，实际可能只有 1~2 条

### 5.2 视频源会被限流 —— `embed_url` 可能全是空的

B 站接口有 **IP 级限流**（实测密集请求后会被整体拒绝一段时间）。触发时后端会自动降级：B 站拿不到就只剩课程平台和图文。

**表现：返回的结果全部 `embed_url` 为空**，也就是全都只能跳转。

**界面应对：**
- 不能假设"至少有一条能站内播"
- 全部是跳转时，仍要正常展示（这时的顺序就是：课程平台 → 图文）
- **不要**因为 `embed_url` 全空就报错或显示"加载失败"

### 5.3 可能一条都搜不到

降级之后仍然可能为空（冷门主题、检索词没匹配上）。

**界面应对：**必须有**空态**，文案参考：「这一章暂时没有找到合适的外部视频」，可选给一个「去 B 站搜索」的外链作为出口。不要留白，也不要显示错误样式 —— 这不是错误。

### 5.4 不要和资源库那个「推荐视频」列表混用

`FundamentalsPage.vue` 现在已经有一处外部视频的展示（`externalVideoResources` / `selectedExternalVideo` / `parseExternalVideo`），但它读的是 `resourceApi.list()`，语义和本接口**完全不同**：

| | 现有那个列表 | 本接口 |
| --- | --- | --- |
| 数据来源 | 整个**资源库**（`resourceApi.list()` 过滤 `resource_type === 'external_video'`） | 按 `(路径, 节点)` **实时检索** |
| 节点归属 | **没有** —— 数据库里 `external_video` 记录只存了 `topic`，没有 `node_id` | 明确的节点 |
| 排序 | **无排序**，列表原顺序 | 按第 4 节的优先级 |
| 结果 | 用户历史上存过的**所有**外部视频混在一起 | 只属于当前节点 |

所以：**同一个用户在不同路径 / 不同章节，那个列表看到的是同一份混合数据**；本接口才是"这一章的"。

接的时候要决定是**替换**掉那套，还是两者并存（并存的话要区分标题，避免用户以为是同一份东西）。

### 5.5 不要塞进现有的「视频」标签页

页面里已经有一个 `resourceView === 'video'` 的标签页，那是**自研生成的视频讲解**（`VideoLessonFrame`，内容是我们自己生成的），和外部视频是**两套东西**。

外部视频目前用的是 `resourceView === 'external_video'`，标签名是**「推荐视频」**。**不要**把两者合并到一个 tab 里。

## 6. 前端需要做的

1. 在 `fundamentalsApi.js` 加一个方法（跟现有 `getNode` 同样的 `unwrap` 写法）：

   ```js
   async getNodeExternalVideos(pathId, nodeId, maxResults = 3) {
     return unwrap(await httpClient.get(
       `/path/${pathId}/node/${nodeId}/external-videos`,
       { params: { max_results: maxResults } },
     ))
   }
   ```

2. 在 `activeNode` 变化时调用（**切换章节才调**，不要每次渲染都调），并处理加载中 / 空 / 失败三种状态。

3. 按第 4 节渲染：`embed_url` 非空走 iframe，为空走跳转；**保持返回顺序**。

4. 补齐交互状态：**默认 / 悬停 / 聚焦 / 禁用 / 加载 / 错误**，沿用现有的设计变量（`--ink` / `--muted` / `--line` / `--paper` / `--accent` / `--accent-deep`）。

5. 桌面和移动宽度都要检查不溢出、不遮挡。

---

## 7. 一句话口径

- 这是**按节点实时检索**的外部视频，不是资源库列表
- **能站内播的排最前面**，前端不要重排
- 结果**可能不相关、可能全是跳转、可能为空** —— 三种都要有界面
- `node_id` 必须前端传 `activeNode.id`，后端不猜
