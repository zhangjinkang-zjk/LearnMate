# LearnMate 功能与后端技术参考

## 1. 文档用途

本文档供比赛文档撰写人员参考，重点说明 LearnMate 的产品功能、个性化学习闭环和可落地的后端技术。本文档不展开页面线框、接口字段或数据库表结构。

## 2. 产品定位

LearnMate 是一个面向垂直领域的个性化学习系统。系统根据用户身份、学习方向、学习目标和能力诊断结果，生成差异化的学习内容和进阶任务，并根据学习过程中的反馈持续调整后续安排。

本次比赛建议选择的垂直方向为：

> 企业知识库与智能体应用开发

该方向包含多个能力模块：

```text
Python 与工程基础
大模型与 Prompt 工程
RAG 与知识库构建
Agent 工具调用与工作流
多智能体协同决策
系统评测与部署
综合项目实训
```

系统不是把这些模块做成相互独立的课程，而是围绕一个方向组织成连续的能力学习过程。

## 3. 完整业务闭环

```text
学习定向
  ↓
方向化能力诊断
  ↓
诊断结果确认
  ↓
学习概览
  ↓
基础讲解
  ↓
阶段复盘
  ↓
进阶学习
  ↓
进阶复盘
  ↓
更新掌握度和后续任务
  ↺ 回到学习概览
```

### 3.1 学习定向

新用户首次使用时完成，收集：

- 用户身份：学生、开发者、产品/业务人员、求职者等；
- 学习方向：用户选择的垂直领域；
- 学习目标：就业、完成项目、转行、掌握基础等；
- 已有基础：编程、后端、大模型、RAG 等；
- 可投入时间和期望完成时间。

学习定向结果会影响后续诊断问题、内容难度、资源类型和进阶任务。

### 3.2 方向化能力诊断

系统根据用户选择的学习方向生成第一轮诊断，不使用完全通用的题目。诊断内容可以包括：

- 基础知识选择题；
- 领域场景判断题；
- 简单代码或配置判断；
- 学习经历和熟悉度自评；
- 与目标岗位或项目相关的短任务。

诊断结果应输出各能力模块的掌握度、薄弱知识点和诊断置信度，而不是只给一个总分。

### 3.3 诊断结果确认

用户查看系统形成的能力画像和初步学习建议后确认：

- 结果符合：确认进入系统；
- 结果不符合：返回修改学习定向或补充诊断；
- 信息不足：继续回答补充问题。

这里的“合格”是指诊断信息足够支撑个性化学习，不是要求新用户先达到某个分数。

### 3.4 学习概览

用户进入系统后的默认功能，集中展示：

- 当前身份、学习方向和主要目标；
- 各能力模块掌握程度；
- 当前薄弱知识点；
- 当前学习阶段和待完成任务；
- 下一步建议、推荐依据和完成条件；
- 基础讲解、迁移练习、综合案例和项目实训的状态。

学习概览的核心作用是回答“我现在的情况是什么，下一步应该做什么”。

信息布局建议采用“事实在左、分析在中、决策在右”的结构：

- 左侧：当前目标、涉及能力模块、掌握度和学习进度；
- 中部：薄弱知识点、近期答题表现和当前阶段说明；
- 最右侧：学习决策，包括决策结论、数据解读、推荐行动、完成条件和下一阶段。

学习决策放在页面最右侧，作为系统分析的最终输出和主要行动区。用户先查看自己的数据和问题，再阅读右侧结论并执行推荐动作。

### 3.5 基础讲解

基础讲解解决“用户是否理解知识”。主要内容包括：

- 经过审核的领域文档；
- 概念、原理和流程拆解；
- 简单示例和图示；
- 思维导图和知识结构；
- AI 换种方式解释、举例和答疑；
- 低难度基础练习。

资源使用原则：文档和知识库是知识主线，思维导图用于结构理解，图片和视频用于示范，PPT 只作为视觉辅助或总结材料，不能替代文档和知识库来源。

### 3.6 阶段复盘

基础讲解完成后，系统根据用户的阅读、提问、答题和练习结果进行复盘，判断：

- 哪些知识点已经掌握；
- 哪些知识点仍然薄弱；
- 是否达到进阶学习条件；
- 应该补基础、针对性巩固还是进入迁移练习。

阶段复盘结果会更新用户掌握度，并影响后续任务和内容生成。

### 3.7 进阶学习

进阶学习解决“用户是否会使用知识”。它不能只是基础讲解内容的重复，也不能只是把题目换成更高难度，而应在以下方面产生区别：

- 使用新的真实或半真实场景；
- 同时调用多个能力模块；
- 需要阅读证据、分析问题和做出判断；
- 要求提交方案、代码、配置、分析结果或项目成果；
- 接受 AI 审核并根据反馈修改。

进阶学习分为三层：

1. **迁移练习**：把刚学的知识应用到相似但不同的场景；
2. **综合案例**：综合使用多个知识模块和资料，分析问题并提交方案；
3. **项目实训**：完成需求分析、方案设计、实现、测试、部署或作品交付。

## 4. 根据学习目标生成进阶内容

同一个学习方向下，不同目标的进阶内容必须不同。

### 4.1 就业目标

围绕目标岗位的真实工作能力生成：

- 接口开发、代码实现、调试和故障排查；
- 岗位场景案例和技术面试题；
- 技术方案讲解和作品展示；
- 岗位能力覆盖和就业差距分析。

最终成果可以是项目作品说明、技术方案、面试讲解记录和岗位能力报告。

### 4.2 完成项目目标

围绕一个明确项目生成连续任务：

- 需求分析；
- 知识库结构设计；
- RAG 检索方案；
- Agent 工作流设计；
- 测试问题和效果评测；
- 部署和项目说明。

最终成果应是可运行的领域智能助手、知识库项目或完整项目报告。

### 4.3 转行目标

围绕原有能力迁移和目标岗位补齐生成：

- 识别用户已有能力可以迁移到什么岗位；
- 补充目标岗位缺失的基础知识；
- 逐步增加岗位场景和综合实践；
- 输出当前能力与目标岗位之间的差距。

最终成果可以是阶段作品、能力差距报告和后续转行学习路线。

### 4.4 掌握基础目标

以理解和巩固为主：

- 概念和原理；
- 基础示例；
- 低难度练习；
- 知识覆盖检查。

达到基础掌握条件后，再推荐适度迁移练习，不强制进入复杂项目。

## 5. 多智能体协同设计

系统至少包含以下职责：

### 5.1 学情诊断 Agent

分析用户身份、学习目标、诊断答案、答题记录和学习行为，形成能力画像，识别掌握度和薄弱知识点。

### 5.2 内容生成 Agent

根据学习方向、用户画像、当前阶段和知识库内容，生成基础讲解、示例、练习、迁移案例、综合案例或项目任务。

### 5.3 内容审核 Agent

检查生成内容是否有知识依据，判断事实准确性、难度适配、知识覆盖、目标匹配和任务完整性。

### 5.4 学习策略 Agent

根据阶段复盘和用户学习目标，决定下一步是补基础、针对性巩固、迁移练习、综合案例还是项目实训。

### 5.5 协同链路

```text
学情分析 -> 知识检索 -> 内容生成 -> 内容审核
    -> 学习策略决策 -> 用户交互 -> 反馈采集 -> 再次决策
```

## 6. 后端技术方案

以下技术优先使用当前项目已有能力，不需要更换整体架构。

### 6.1 FastAPI

继续作为后端 Web API 框架，承载：

- 用户和认证；
- 学习定向和诊断；
- 用户画像和掌握度；
- 知识库和资源；
- 基础讲解和进阶任务；
- 学习反馈和阶段复盘；
- Agent 任务和生成状态。

### 6.2 Tortoise ORM + MySQL

继续保存系统的核心业务数据：

- 用户身份和学习定向；
- 诊断题目、答案和模块得分；
- 用户画像和掌握度；
- 学习阶段、任务和完成记录；
- 领域资源和知识库文档；
- 用户答题、案例提交和学习反馈；
- Agent 执行记录、审核结果和学习决策。

### 6.3 Redis

用于：

- 异步资源生成状态；
- Agent 任务进度；
- SSE 事件缓存和断线恢复；
- 生成结果缓存；
- 阶段复盘和推荐决策的临时状态。

### 6.4 LangGraph

复用已有的路径生成和资源生成图，将多智能体编排为有状态流程：

- Leader/规划节点：拆解学习目标和任务；
- Executor/执行节点：并行生成文档、案例、练习等资源；
- Reviewer/审核节点：检查准确性、难度和来源；
- 策略节点：决定是否重试、补充或调整后续任务。

基础讲解和进阶学习可以共用生成图，但通过阶段、学习目标和任务类型使用不同的提示词和输出模板。

### 6.5 LangChain/OpenAI 接口

继续用于：

- 大模型调用；
- 提示词管理；
- 结构化结果解析；
- 诊断题和反馈生成；
- 基础讲解和案例生成；
- 学习策略判断。

### 6.6 BGE 嵌入和向量检索

用于领域知识库：

- 文档清洗、切分和向量化；
- 根据当前知识点检索相关领域内容；
- 为生成内容提供依据；
- 保存来源文档和片段，支持结果追溯；
- 检查知识覆盖率和引用完整性。

### 6.7 SSE 流式事件

继续用于向前端推送：

- 学情分析开始和完成；
- 知识检索状态；
- 内容生成进度；
- 审核结果；
- 学习策略决策；
- 资源生成和保存状态。

这些事件不仅用于动画展示，还要保存为学习过程记录，便于复盘和比赛演示。

### 6.8 现有业务能力复用

当前项目已有的以下能力可以直接作为基础：

- 用户认证和用户管理；
- 用户画像、能力雷达和掌握度；
- 知识库上传、切分、向量化和检索；
- 资源生成和资源审核；
- 学习路径和节点；
- 题目、考试记录和知识掌握度；
- 学习课堂、问答和互动反馈；
- 文档、PPT、思维导图、案例、练习、视频和图片资源。

本次重点是把这些能力收敛到“学习定向、诊断、基础讲解、进阶学习、复盘”的统一流程中，而不是重新开发一套平行系统。

## 7. 需要补充的后端能力

### 7.1 学习会话

把一次连续学习抽象成学习会话，统一关联用户、方向、目标、当前阶段、当前任务、资源和反馈。

### 7.2 目标策略

后端需要根据主要学习目标选择进阶任务模板：

```text
就业 -> 岗位任务、面试题、作品说明
完成项目 -> 项目里程碑、设计、实现、测试、部署
转行 -> 能力迁移、基础补齐、岗位差距、阶段作品
掌握基础 -> 概念、示例、基础练习、覆盖检查
```

### 7.3 学习场景编排

每个任务应返回有顺序的资源组合，而不是返回一堆没有关系的文件：

```text
文档讲解 -> 思维导图 -> 可选图示/PPT -> 案例 -> 练习 -> 复盘
```

进阶任务则可以是：

```text
任务背景 -> 证据材料 -> 用户操作 -> 方案提交 -> Agent 审核 -> 下一任务
```

### 7.4 质量评测

需要增加可重复的测试数据和评测流程，关注：

- 领域知识覆盖率；
- 资源难度与用户掌握度匹配度；
- 内容审核通过率；
- 疑似事实错误和幻觉率；
- 不同用户目标下的任务差异；
- 基础到进阶的解锁判断准确性。

## 8. 前后端闭环要求

一次学习行为至少应产生以下结果：

```text
用户阅读/提问/答题/提交案例
  -> 记录学习行为
  -> 更新知识点掌握度
  -> 重新识别薄弱点
  -> 生成学习策略决策
  -> 调整下一项内容或任务
```

不能只生成资源而不记录使用结果，也不能只记录分数而不改变后续学习安排。

## 9. 比赛演示建议

建议用“完成项目”目标演示完整链路：

```text
选择身份和方向
  -> 选择目标：完成项目
  -> 完成方向化能力诊断
  -> 确认诊断结果
  -> 学习概览显示 RAG 薄弱点
  -> 基础讲解：阅读领域文档并完成练习
  -> 阶段复盘：达到迁移条件
  -> 进阶学习：分析企业知识库问答问题
  -> 提交解决方案
  -> 多智能体审核并生成下一项项目任务
```

为了体现个性化，至少准备三类用户：

- 有后端基础但缺少 AI 实践的开发者；
- 有 AI 基础但缺少工程经验的学习者；
- 无相关经验、需要从基础开始的转行者。

## 10. 实施重点

1. 先确定一个垂直领域和一套领域知识库；
2. 完成学习定向、方向化诊断和诊断结果确认；
3. 将现有画像、知识库、资源生成和题目能力接入学习概览；
4. 做出文档主线的基础讲解流程；
5. 按就业、完成项目、转行目标实现差异化进阶模板；
6. 增加阶段复盘、掌握度更新和下一步决策；
7. 保存 Agent 过程、知识来源和审核结果；
8. 准备测试用例、质量指标和比赛演示脚本。

## 11. 最终产品定义

> LearnMate 是一个面向垂直领域的个性化学习系统。用户首次通过学习定向确定身份、学习方向和学习目标，通过方向化能力诊断建立初始画像并确认学习方案；进入系统后，学习概览根据掌握程度提供下一步建议，基础讲解帮助用户理解领域知识，进阶学习则根据就业、完成项目或转行等目标生成不同的迁移、案例和项目任务。系统基于现有 FastAPI、MySQL、Redis、LangGraph、LangChain、向量检索和 SSE 等技术，通过多智能体协同完成内容生成、审核和学习策略调整，并根据用户反馈持续更新后续任务，形成完整的个性化学习闭环。
